# Monitoring — Beszel + Dozzle

Stack file: [`docker-compose.monitoring.yml`](../docker-compose.monitoring.yml) (project `monitoring`).
Deployed automatically by the **Deploy infra** workflow after `data` and `edge`.

| Tool | What it shows | URL (Tailscale only) | RAM limit |
|------|---------------|----------------------|-----------|
| **Beszel** hub | CPU / RAM / disk / network for the host **and per container**, history graphs, alerts | `http://ys-vps:8090` | 128M |
| Beszel agent | Collects the stats (host network, Docker socket read-only) | — (unix socket, no port) | 64M |
| **Dozzle** | Live + searchable logs of every container | `http://ys-vps:8081` | 64M |

Neither is reachable from the internet: ports are bound to `TAILSCALE_IP` only.
`ys-vps` resolves via MagicDNS; otherwise use the `100.x.x.x` IP.

> **Not a database UI.** Beszel shows how much CPU/RAM Postgres and Redis use, Dozzle shows
> their logs — but neither lets you browse tables or keys. For Postgres use DBeaver over
> Tailscale (`ys-vps:5432`), or the web UIs in the `tools` stack: **pgweb** at `http://ys-vps:8082`
> and **Redis Commander** at `http://ys-vps:8083` (credentials `TOOLS_USER` / `TOOLS_PASSWORD` in `.env`).

## First-time setup (Beszel agent)

The agent needs a **key + token generated by the hub**, so it is behind the compose
profile `agent` and starts only after you enable it.

1. **Deploy** (push or run **Deploy infra**). Hub and Dozzle start; agent does not yet.
2. Open `http://ys-vps:8090` → create the **admin account** (first visit only).
   Do this right away — until then anyone on your tailnet could claim it.
3. Click **Add System**:
   - Name: `ys-vps`
   - Host / IP: `/beszel_socket/beszel.sock`  ← the unix socket, not an IP
   - Copy the **Key** (`ssh-ed25519 AAAA…`) and the **Token**.
   - Click **Add system**.
4. On the VPS, edit `/opt/ys-infra/.env`:

   ```bash
   BESZEL_AGENT_KEY="ssh-ed25519 AAAA..."
   BESZEL_AGENT_TOKEN=xxxxxxxx-xxxx-...
   COMPOSE_PROFILES=agent
   ```

   `KEY` is required. `TOKEN` is optional: without it the agent logs
   `must set TOKEN` and serves over the unix socket only. That's enough on a single host.

5. Start the agent (or re-run **Deploy infra** from GitHub):

   ```bash
   cd /opt/ys-infra
   docker compose -f docker-compose.monitoring.yml up -d --wait
   ```

6. In the Beszel UI the system turns **green** within ~1 minute. Containers
   (`postgres`, `redis`, `traefik`, …) appear under the system's **Containers** tab.

### Recommended Beszel settings

- **Settings → Notifications**: add a Telegram bot or email (SMTP) for alerts.
- **System → Alerts (bell icon)**: e.g. CPU > 80% for 10 min, Memory > 85%,
  Disk > 80%, Status down.
- **Settings → General**: keep history retention small if disk is tight.

## Dozzle

Nothing to set up. Open `http://ys-vps:8081`:
- Pick a container on the left; logs stream live. `Ctrl/Cmd + K` to jump.
- Search with plain text or regex; filter by level.
- Pin multiple containers to see logs side by side.

Hardened defaults in compose: **read-only** (`DOZZLE_ENABLE_ACTIONS=false`,
`DOZZLE_ENABLE_SHELL=false`) — no start/stop/exec from the browser. Access control
is Tailscale itself; there is no Dozzle login.

> Logs come from Docker's json-file driver, rotated at 10 MB × 3 files per container,
> so Dozzle shows the last ~30 MB per container, not full history.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Beszel system stays **red / pending** | Agent running? `docker ps --filter name=beszel-agent`. `COMPOSE_PROFILES=agent` set in `.env`? Host field must be `/beszel_socket/beszel.sock`. |
| Agent logs `invalid key` / auth error | `BESZEL_AGENT_KEY` must be the whole line incl. `ssh-ed25519`, in quotes. Re-copy from **Add System** dialog. |
| No container stats in Beszel | Docker socket mount missing / wrong. `docker exec beszel-agent ls -l /var/run/docker.sock`. |
| `cannot assign requested address` on 8090/8081 | `TAILSCALE_IP` wrong or Tailscale down — see [tailscale.md](tailscale.md). |
| Lost Beszel admin password | `docker exec -it beszel /beszel superuser upsert you@example.com NEWPASS` |

Logs of the monitoring tools themselves:

```bash
docker compose -f docker-compose.monitoring.yml logs -f --tail 100
```
